# Отчёт по тестовому заданию: постобработка OCR паспорта РФ

## 1. Введение и постановка задачи

В задаче верификации паспортов РФ цена ошибки первого рода (принятие некорректного или недействительного документа) несоизмеримо выше цены ошибки второго рода (отклонение документа с просьбой переснять). Ошибочно принятый паспорт в финансовом или KYC-пайплайне ведет к рискам регуляторных штрафов и мошенничества.

**Критерий верного решения:**
1. Все 10 полей документа совпадают с эталонной разметкой (без учёта регистра и повторных пробелов).
2. Паспорт действителен на опорную дату **01.10.2026**.

**Цель:** максимизировать долю автоматически принимаемых документов (Recall) при обеспечении околонулевого уровня ошибок (Precision $\to 100\%$).

---

## 2. Анализ данных и ключевые инсайты

В ходе исследовательского анализа 3000 документов обучающей выборки (`train_predictions.jsonl`) и разметки (`train_labels.jsonl`) были выявлены следующие фундаментальные закономерности:

1. **Машиночитаемая зона (MRZ):**
   - Присутствует у 93.9% документов в train и 94.7% в test.
   - Внутренние паспорта РФ используют строгий двухстрочный стандарт MRZ (Приказ ФМС РФ № 294 от 12.07.2011).
   - Строка 1 содержит взаимно-однозначную символьную транслитерацию ФИО (например, `3 -> Ч`, `4 -> Ш`, `9 -> Ь`, `8 -> Я`, `7 -> Ю`, `Q -> Й`), которая однозначно декодируется обратно в кириллицу.
   - Строка 2 содержит серию (4 цифры) и номер (6 цифр), дату рождения, пол, дату выдачи и код подразделения, защищённые тремя контрольными суммами ICAO (алгоритм с весами 7-3-1).

2. **Синергия MRZ и визуальной зоны (VIZ):**
   - При совпадении данных MRZ (с валидными чексуммами) и VIZ по 8 ключевым полям (`Last_name_ru`, `First_name_ru`, `Middle_name_ru`, `Sex_ru`, `Birth_date`, `Issue_date`, `Issue_organisation_code`, `Licence_number`) эмпирическая ошибка распознавания стремится к нулю.
   - На 3000 документах train при взаимном согласии MRZ и VIZ не зафиксировано ни одной реальной ошибки в номерах и датах.

3. **Срок действия паспорта на 01.10.2026:**
   - По «Положению о паспорте гражданина РФ» паспорт подлежит обязательной замене по достижении 20 и 45 лет (выдается с 14 лет).
   - В train выявлено 105 документов с истекшим сроком (например, гражданину 32 года, а паспорт выдан в 14 лет и не менялся в 20 лет). В test таких документов 73. Принятие любого из них трактуется как ошибка.

4. **Ахиллесова пята OCR — поля `Birth_place_ru` и `Issue_organization_ru`:**
   - Эти два поля отсутствуют в MRZ. На них приходится 77.5% всех ошибок базовой модели OCR.
   - Справочник `subdivisions.csv` содержит актуальные и исторические наименования подразделений, но штамп в паспорте часто содержит вариативные сокращения (например, `ОТДЕЛ ПО ВОПРОСАМ МИГРАЦИИ...` вместо `ОТДЕЛЕНИЕМ УФМС...`, `ОБЛАСТИ` вместо `ОБЛ.`). Прямая замена текста на справочник снижает точность до 5.9%. Однако лексикон из `subdivisions.csv` и `train_labels.jsonl` даёт надёжный словарь допустимых слов (7921 слово).
   - Анализ показал, что 38% грубых ошибок в этих полях вызваны не опечатками в символах, а пропуском строк детектором OCR (высота поля $h > 45$ px при наличии лишь одной прочитанной строки).

## 3. Архитектура алгоритма постобработки (`postprocess.py`)

Разработан детерминированный многоуровневый фильтр с каскадной валидацией:

```
[Входной документ]
        │
        ├─► 1. Валидация MRZ: длина строк, префикс PNRUS, проверка 3 чексумм ICAO (7-3-1)
        │      └─ [Fail] ──► REJECT
        │
        ├─► 2. Проверка срока действия паспорта на 01.10.2026 (правила 14 / 20 / 45 лет)
        │      └─ [Fail / Просрочен] ──► REJECT
        │
        ├─► 3. Перекрёстная сверка MRZ и VIZ по 8 полям (номера, даты, пол, ФИО)
        │      └─ [Несовпадение хотя бы в 1 символ] ──► REJECT
        │
        ├─► 4. Контроль полей Birth_place_ru и Issue_organization_ru:
        │      ├─ Посимвольная уверенность: min(char_conf) >= 0.985, field_conf >= 0.98
        │      ├─ Геометрический контроль детектора (соответствие высоты бокса числу строк)
        │      ├─ Структурно-синтаксический контроль (валидное начало, отсутствие висячих предлогов)
        │      ├─ Фильтр аномальных OCR-кластеров (слова на 'ЧС', 'Ь', 'Ъ')
        │      └─ Словарный контроль подразделения (все слова входят в доверенный лексикон)
        │      └─ [Fail] ──► REJECT
        │
        ▼
   [ACCEPT + 10 верифицированных полей]
```

### Детали фильтрации:
- **`Middle_name_ru`:** При отсутствии отчества в VIZ и разделителе `<` в MRZ поле корректно определяется как пустая строка `""` (100% точность).
- **`Sex_ru`:** Строго `'МУЖ.'` или `'ЖЕН.'`, синхронизировано с символами `M`/`F` в MRZ.
- **Геометрия:** Если поле `Issue_organization_ru` имеет высоту бокса $>45$ px, но детектор вернул только 1 строку (или $>75$ px при 2 строках), документ бракуется как неполно распознанный.
- **Синтаксис:** Организация обязана начинаться с регламентных терминов (`ОТДЕЛ`, `УФМС`, `МВД`, номер ОМ и др.) и не может обрываться на предлогах (`ПО`, `В`, `И`).

### Обязательный прогноз:
- **Будет принято документов:** **554** из 2000 (**27.7%**).

  *(С учётом естественного фонового шума ручной разметки $\approx 0.5\% - 0.9\%$ статистически ожидается от 2 до 5 формальных несовпадений с эталоном, аналогичных опечаткам в train).*

## 6. Воспроизводимость и соответствие требованиям

1. **Автономность:** Решение реализовано на чистом Python 3 без сторонних зависимостей (только стандартные модули `json`, `csv`, `re`, `datetime`, `sys`, `os`). Работает на CPU, без интернета.
2. **Время работы:** Менее 1.5 секунд на 2000 документов.
3. **Команда запуска:**
   ```bash
   python postprocess.py data/test_predictions.jsonl answers.jsonl
   ```
4. **Валидация формата:** Результирующий файл `answers.jsonl` строго содержит 2000 строк валидного JSON, с полями только для принятых документов.
